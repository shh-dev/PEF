# 4.18 배포 품질

적용: 전 유형 ● (배포 안 하는 라이브러리는 릴리스 관점으로)
**배포·운영 변경은 사용자 승인 없이 수행하지 않는다.** 설정 파일을 읽고 판단만 한다.

| ID | 확인 방법 | 문제 기준 | 기본 심각도 |
|---|---|---|---|
| DP-01 | CI/CD 설정 존재, 배포 전 테스트·린트·빌드 게이트 | 검사 없이 배포 | P2 |
| DP-02 | 환경 분리(local/dev/stg/prod) 설정, 개발용 서비스의 운영 사용 | dev가 prod DB를 공유 등(알고 있는 의도는 `AcceptedRisk`) | P1 |
| DP-03 | 빌드 재현성: lockfile 커밋, 버전 고정, Node/Python 버전 명시 | lockfile 없음, 버전 미고정 | P3 |
| DP-04 | 시크릿 관리: CI/배포 환경 변수 사용, 저장소 비포함 (→ 10장) | 저장소에 평문 | P0 |
| DP-05 | 배포 후 검증(스모크 테스트·헬스체크) | 배포 성공 = 컨테이너 시작뿐 | P3 |
| DP-06 | 롤백 방법 문서·검증 | 롤백 절차 없음 | P2 |
| DP-07 | DB 마이그레이션이 배포 흐름에 포함, 순서 보장 | 수동·순서 불명 | P2 |
| DP-08 | 릴리스 이력·버전·변경 기록 | 무엇이 언제 배포됐는지 모름 | P3 |
| DP-09 | 컨테이너/서버 설정: 루트 실행, 불필요 포트, 최신 베이스 이미지 | 루트로 실행, 과다 노출 | P2 |
