# 4.1 기능 완결성

적용: UI앱 ● / API ● / CLI·라이브러리 ● / 배치 ●
기본 원칙: 정적 확인 우선. 실제 동작 확인(실행·클릭)은 테스트 환경에서 승인 후.

| ID | 확인 방법 | 문제 기준 | 기본 심각도 |
|---|---|---|---|
| F-01 | 라우트/화면/버튼 핸들러를 grep해 빈 핸들러·`TODO`·`not implemented` 찾기 | 눌러도 아무 일도 없는 요소, 미구현 표식 | P2 |
| F-02 | 엔티티별 C/R/U/D 구현 대조표 작성 | 생성만 있고 수정·삭제 없음 등 누락 | P2 |
| F-03 | 저장·전송 코드의 실패 분기(catch/에러 응답) 확인 | 실패해도 성공처럼 표시, 에러 삼킴 | P1 |
| F-04 | 삭제 흐름: 확인창·소프트삭제·복구 수단 | 확인 없이 영구 삭제 | P1 (데이터 유실이면 P0) |
| F-05 | 생성 요청에 멱등키/중복 방지/버튼 잠금 | 더블클릭·재시도 시 중복 생성 | P2 |
| F-06 | 권한별 기능 노출·서버 검사 대조 | 버튼만 숨기고 서버는 허용 | P1 (보안 4.13과 연동) |
| F-07 | 상태 전환(주문·승인 등) 허용 전이표와 코드 대조 | 허용 안 된 전이 가능 | P2 |
| F-08 | 서버 측 입력 검증 존재 여부 | 클라이언트 검증만 있음 | P1 |
| F-09 | 비정상 데이터(null·빈값·초대형·특수문자) 처리 경로 | 크래시·흰 화면 | P2 |
| F-10 | 네트워크 실패·타임아웃·세션 만료 처리 | 무한 로딩, 조용한 실패, 입력 손실 | P2 |
| F-11 | 새로고침·뒤로가기 시 상태 복원 | 진행 중 작업 소실 | P3 |
| F-12 | 부분 실패(일괄 처리 중 일부 실패) 보고 방식 | 일부만 반영되고 알림 없음 | P1 |
| F-13 | 기능 간 연결(생성 후 목록 갱신, 링크 대상 존재 등) | 깨진 링크, 갱신 안 됨 | P3 |
