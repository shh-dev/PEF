### 소스 범위·확인 방식 (에이전트 분담용)

| 파일 | 주로 보는 소스 | 정적으로 가능한 정도 |
|---|---|---|
| 01 기능, 02 UX, 20 일관성 | 화면 코드 + 서버 로직 | 일부 (실제 동작은 실행 필요) |
| 03~07 시각·인터랙션·상태·반응형·접근성 | 컴포넌트·CSS | 구조는 가능, 실화면·스크린리더는 실측 필요 |
| 08~09, 19 구조·품질·유지보수 | 전체 소스, 설정 | 대부분 가능 (Knip 등 도구 있으면 정확) |
| 10 성능 | 번들·이미지·설정 | 정적 단서만. 수치는 빌드·측정 필요 |
| 11~12, 13~15 API·DB·보안·개인정보·신뢰성 | 서버 코드, 마이그레이션, 설정 | 대부분 가능, 라이브 DB/권한은 `needsLiveCheck` |
| 16 테스트 | 테스트 파일·CI | 존재 여부 가능, 통과 여부는 실행 필요 |
| 17~18 관측성·배포 | 설정, CI, 문서 | 대부분 가능 |

판정 값은 `docs/SCORING.md` §4-1(Clean/Confirmed/Suspected/RequiresManualReview/NotTested/NotApplicable). 파일 ↔ SPEC 영역: 01→4.1 … 20→4.20 (파일 번호 = 4.x의 x). 서버리스 환경에서 해당 없는 항목은 `NotApplicable` + 사유.
