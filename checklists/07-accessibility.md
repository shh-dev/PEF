# 4.7 접근성

적용: UI앱 ● / CLI ○
기준: WCAG 2.2 AA. 자동 도구(axe-core)는 일부만 잡는다 → 자동 통과 ≠ 접근 가능. 수동 항목은 `RequiresManualReview`.

| ID | 확인 방법 | 문제 기준 | 기본 심각도 |
|---|---|---|---|
| A-01 | 이미지 `alt`, 아이콘 버튼 `aria-label` | alt 누락, 이름 없는 버튼 | P2 |
| A-02 | 폼 입력 `<label>` 연결, 오류 메시지 연결(`aria-describedby`) | 레이블 없음 | P2 |
| A-03 | 시맨틱 요소(button/a/nav/main/heading 순서) | `div onClick`으로 버튼 구현 | P2 |
| A-04 | 색상 대비: 본문 4.5:1, 큰 글자·UI 3:1 | 미달 | P2 |
| A-05 | 키보드만으로 전 기능 사용, 포커스 표시 | 마우스 전용 기능, 포커스 안 보임 | P1 |
| A-06 | 모달 포커스 트랩/복귀, 스킵 링크 | 포커스가 뒤로 샘 | P2 |
| A-07 | ARIA 오용(역할 중복·잘못된 속성) | 네이티브로 되는데 ARIA 남발 | P3 |
| A-08 | 색만으로 상태 표현 | 색맹이면 구분 불가 | P3 |
| A-09 | 터치 타깃 ≥ 24px(WCAG 2.2 최소) 권장 44px | 작은 타깃 | P3 |
| A-10 | 동적 변화 알림(`aria-live`), 토스트 읽힘 | 스크린리더에 안 읽힘 | P3 |
| A-11 | 스크린리더 실제 확인 | 수동 확인 필요 항목으로 표기 | – |
