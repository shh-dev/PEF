# 4.11 API 효율

적용: API ● / UI앱 ○ (호출하는 쪽) / 배치 ○

| ID | 확인 방법 | 문제 기준 | 기본 심각도 |
|---|---|---|---|
| AP-01 | 같은 데이터를 여러 컴포넌트/함수가 중복 요청 | 동일 요청 반복 | P3 |
| AP-02 | 응답 필드 중 실제 사용 비율, 불필요 데이터 전송 | 큰 객체를 통째로 전송 | P3 |
| AP-03 | 목록 API 페이지네이션/상한 | 무제한 조회 | P1 |
| AP-04 | 외부 호출 timeout·retry(백오프)·상한 | timeout 없음, 무한 재시도 | P2 |
| AP-05 | rate limit 적용(특히 로그인·비용 큰 엔드포인트) | 제한 없음 | P2 |
| AP-06 | 엔드포인트 인증/인가 적용 대조표 | 인증 없는 민감 엔드포인트 | P0~P1 (→ 4.13) |
| AP-07 | 오류 응답 형식 일관성, 내부 정보(스택) 노출 | 형식 제각각, 스택 노출 | P2 |
| AP-08 | API 버전/하위 호환 정책 | 필드 이름 변경이 무고지 | P3 |
| AP-09 | 쓰기 API 멱등성(재시도 안전) | 재시도 시 중복 처리 | P2 |
| AP-10 | 비동기 경합: 느린 응답이 최신 상태를 덮어씀 | 오래된 응답이 최신 화면을 덮음 | P2 |
| AP-11 | 캐시 헤더·ETag·클라이언트 캐시 | 매번 풀 재요청 | P3 |
