# 4.9 코드 품질

적용: 전 유형 ●
도구 후보: Knip(미사용), 타입체커, 린터. 도구 없으면 grep 근사 + 신뢰도 낮음 표기.

| ID | 확인 방법 | 문제 기준 | 기본 심각도 |
|---|---|---|---|
| C-01 | 중복 코드(비슷한 함수 복붙) 탐지 | 3곳 이상 동일 로직 | P3 |
| C-02 | 미사용 파일/export/패키지 (Knip 등) | 사용처 0건 | P3 |
| C-03 | 함수 길이·분기 수·중첩 깊이 | 매우 길고 복잡한 함수/컴포넌트 | P3 |
| C-04 | 타입 안정성: `any`, 타입 무시 주석, strict 여부 | strict 꺼짐, any 남발 | P3 |
| C-05 | 예외 처리: 빈 catch, 에러 삼킴, 미처리 Promise | 에러를 삼킴 | P2 |
| C-06 | 매직 넘버·하드코딩 문자열·반복 상수 | 의미 불명 숫자/URL 반복 | P3 |
| C-07 | 명명·컨벤션 일관성, 린터 설정 존재 | 린터 없음, 이름 규칙 혼재 | P4 |
| C-08 | **과잉 구현 탐지 (ponytail)**: 안 쓰는 래퍼·확장점·옵션, 표준/한 줄로 되는데 직접 구현, 안 깔아도 되는 라이브러리 | 아래 예시 중 하나라도 해당 | P3 |
| C-09 | console.log/디버그 코드 잔존 | 운영 코드에 디버그 출력 | P4 |
| C-10 | 주석 처리된 죽은 코드 | 대량 잔존 | P4 |
| C-11 | 테스트 가능성: 순수 함수 분리, 외부 의존 주입 | 테스트 불가한 구조 | P3 |

C-08 예시: 구현체 1개뿐인 인터페이스/팩토리, 한 곳에서만 쓰는 유틸 래퍼, 쓰이지 않는 설정 옵션, `lodash` 하나로 쓰는 함수 1개, 네이티브 `fetch`/`Array` 메서드로 되는 것을 위한 패키지.
수정 시 원칙: 필요한 만큼만, 줄 수 자체가 목적 아님(가독성·안정성 우선), 새 의존성은 승인.
