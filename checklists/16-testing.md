# 4.16 테스트 체계

적용: 전 유형 ●
**테스트가 없거나 부족하면 수정 단계에서 "안전하다" 판정 불가** → 수정 전 특성화 테스트(현재 동작 고정)를 먼저 만든다.
테스트 실행은 승인된 명령만(`package.json` scripts 속 임의 스크립트 신뢰 금지, 내용 확인 후 실행).

| ID | 확인 방법 | 문제 기준 | 기본 심각도 |
|---|---|---|---|
| T-01 | 테스트 파일/러너 설정 존재, 실행 명령 | 테스트 없음 | P2 |
| T-02 | 핵심 흐름(로그인·결제·저장 등) 테스트 유무 | 핵심 흐름 무테스트 | P2 |
| T-03 | 테스트 통과 여부(승인 후 실행) | 기존 테스트 실패 | P1 |
| T-04 | 테스트 안정성(플레이키), 실행 시간 | 간헐 실패, 매우 느림 | P3 |
| T-05 | 커버리지(핵심 모듈 기준, 총량 수치에 집착 금지) | 핵심 로직 0% | P3 |
| T-06 | 통합/E2E, API 계약 테스트 유무 | 계약 변경 감지 수단 없음 | P3 |
| T-07 | 접근성·보안·성능 자동 테스트 유무 | 없음 | P4 |
| T-08 | CI에서 테스트 자동 실행 | 수동 실행뿐 | P3 |
| T-09 | 회귀 방지: 버그 수정 시 재현 테스트 추가 관행 | 같은 버그 재발 이력 | P3 |
