# 4.20 제품 일관성

적용: UI앱 ● / API ○ / CLI ○
핵심: **같은 기능은 같게 동작하고 같게 보인다.** 단, 의도적으로 다르게 만든 차이(예: 채널별 규칙)는 버그가 아니므로 사용자에게 먼저 확인하고 `NotApplicable`로 기록한다. 임의로 통일 제안·수정 금지.

| ID | 확인 방법 | 문제 기준 | 기본 심각도 |
|---|---|---|---|
| CN-01 | 동일 기능 화면들(목록·폼·모달)의 동작 비교 | 비슷한 화면인데 동작 규칙이 다름 | P3 |
| CN-02 | 버튼 크기·간격·위치 규칙 | 같은 역할 버튼이 화면마다 다름 | P3 |
| CN-03 | 상태 표시(로딩·성공·오류) 방식 통일 | 화면마다 다른 표현 | P3 |
| CN-04 | 오류 메시지 형식·어조 | 존댓말/반말, 형식 혼재 | P4 |
| CN-05 | 날짜·시간·숫자·금액 표기 (KST, 24시간제, 천 단위 쉼표 등 프로젝트 규칙) | 화면마다 표기 다름 | P3 |
| CN-06 | 용어 통일 (→ UX-03) | 같은 개념 다른 말 | P3 |
| CN-07 | 모바일/데스크톱 경험 격차 | 모바일에서 기능 누락 | P2 |
| CN-08 | 디자인 토큰 사용 일관성 (→ V-05) | 토큰 우회 하드코딩 | P3 |
| CN-09 | API 응답/에러 구조 통일 | 엔드포인트마다 형태 다름 | P2 |
