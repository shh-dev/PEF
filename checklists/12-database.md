# 4.12 DB 및 데이터 품질

적용: API ● / 배치 ● / UI앱 ○
**운영 DB 직접 조회·쓰기 금지.** 스키마/마이그레이션/쿼리 코드를 정적으로 본다. 실제 DB 확인은 읽기 전용 + 사용자 승인.

| ID | 확인 방법 | 문제 기준 | 기본 심각도 |
|---|---|---|---|
| D-01 | 자주 쓰는 WHERE/JOIN/ORDER 컬럼과 인덱스 대조 | 인덱스 없는 대형 테이블 조회 | P2 |
| D-02 | 루프 안 쿼리(N+1) | 목록 N건에 쿼리 N회 | P2 |
| D-03 | 다중 쓰기 작업의 트랜잭션 | 일부만 반영될 수 있음 | P1 (유실이면 P0) |
| D-04 | FK·UNIQUE·NOT NULL 제약 | 정합성을 코드로만 보장 | P2 |
| D-05 | 동시 수정 충돌 대책(낙관적 락/버전) | 마지막 저장이 조용히 덮어씀 | P1 |
| D-06 | 마이그레이션: 순서·롤백·파괴적 변경(drop/rename) | 롤백 불가한 파괴적 변경 | P1 |
| D-07 | 삭제 정책: 소프트삭제/보관/연쇄 삭제 | CASCADE로 의도치 않은 대량 삭제 | P1 |
| D-08 | 백업 존재·주기·복원 검증 기록 | 백업 없음/복원 미검증 | P1 |
| D-09 | 중복 데이터 방지(유니크 키) | 같은 건 중복 저장 가능 | P3 |
| D-10 | 개인정보 저장 범위(→ 4.14) | 불필요한 개인정보 저장 | P2 |
| D-11 | 목록 쿼리 `SELECT *`·무제한 | 과다 조회 | P3 |
