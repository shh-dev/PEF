# 점수 산출 방법 (SPEC §6 구체화)

SPEC은 7개 가중치만 정의한다. 에이전트마다 점수가 달라지지 않도록 계산 방식을 여기서 고정한다. 이 점수는 PEF 자체 휴리스틱이며 절대 기준이 아니다.

## 1. 20개 영역 → 7개 점수 영역 매핑

| 점수 영역 | 기본 가중치 | 포함 영역 |
|---|---|---|
| 기능 완결성 | 20 | 4.1 |
| UX/UI 완성도 | 20 | 4.2 4.3 4.4 4.5 4.6 4.7 4.20 |
| 코드 및 아키텍처 | 15 | 4.8 4.9 |
| 성능 및 경량화 | 15 | 4.10 4.11 |
| 보안 및 개인정보 | 15 | 4.13 4.14 |
| 안정성 및 테스트 | 10 | 4.12 4.15 4.16 |
| 운영 및 유지보수 | 5 | 4.17 4.18 4.19 |

## 2. 영역 점수 (0~100)

영역 점수 = 100 − Σ(Finding 감점), 최소 0.

| 심각도 | Confirmed 감점 | Suspected 감점 |
|---|---|---|
| P0 | 40 | 20 |
| P1 | 15 | 8 |
| P2 | 6 | 3 |
| P3 | 2 | 1 |
| P4 | 0 | 0 |

- `FalsePositive`, `NotApplicable`, `AcceptedRisk`는 감점하지 않는다(단 `AcceptedRisk`는 보고서에 따로 나열).
- 같은 원인의 중복 Finding은 하나로 합쳐 한 번만 감점한다.
- `Not Tested` 항목은 감점도 가점도 없다. 대신 **커버리지**에 반영한다.

## 3. 점수 영역 점수와 총점

- 점수 영역 점수 = 포함된 *적용 가능한* 영역 점수의 평균.
- 총점 = Σ(가중치 × 점수 영역 점수) / Σ(적용 가능한 점수 영역의 가중치).
- 앱 프로파일(PLAYBOOK §1.5)로 제외한 영역/점수 영역은 분모에서 빼고, **무엇을 왜 뺐는지** 보고서에 적는다. 가중치를 바꿨다면 기본값 대비 변경 내역을 적는다.

## 4. 커버리지와 신뢰도

- 커버리지 = (검사 완료한 체크리스트 항목 수) / (적용 대상 항목 수), 영역별·전체.
- 커버리지 < 50%인 점수 영역은 숫자 대신 `측정 불충분`으로 표시한다. 총점은 참고용이며 신뢰도 `낮음`.
- 커버리지 50~80% → 신뢰도 `중간`, 80% 이상 → `높음`.
- 총점은 항상 `점수 (커버리지 %, 신뢰도)`로 같이 쓴다. 예: `72점 (커버리지 64%, 중간)`.

## 5. 출시 차단 (점수와 무관)

다음 중 하나라도 있으면 점수와 상관없이 `출시 차단`:
- Confirmed P0 Finding
- Confirmed 데이터 유실 가능 결함
- Suspected P0는 `출시 보류 – 수동 확인 필요`로 별도 표시

## 6. 전후 비교

개선 전후는 **같은 체크리스트 범위·같은 가중치**로 비교한다. 범위가 달라지면 비교 불가(`Inconclusive`)로 표기한다. 점수 상승만으로 개선을 주장하지 않고, 성능은 측정값, 회귀는 테스트 결과로 함께 제시한다.
